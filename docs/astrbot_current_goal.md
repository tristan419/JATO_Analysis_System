# AstrBot Current Goal

## 1. 当前目标

把 `/astrbot` 做成一个能够泛化的、以真实数据为先的汽车市场分析 Agent：先理解国家、车型、竞品和业务问题，再通过工具取得证据，最后由模型基于证据生成结论，并把证据呈现为可复用的图表、表格、指标和汇报块。

目标不是继续增加“已知问题对应一段规则答案”，也不是让 AstrBot 更擅长解释它准备调用什么工具。目标顺序固定为：

1. 正确理解问题和业务对象。
2. 形成可执行的证据计划。
3. 调用真实数据工具并取得足够证据。
4. 用统一的 Composer 结构生成有证据支持的业务结论。
5. 在证据不足时说明边界，同时继续给出可执行的分析框架和补证动作。
6. 根据问题自动生成真正有用的图表、表格和 PPT-ready 内容。
7. 用未参与开发的盲测问题验证泛化能力，并与 CountryCopilot 做真实业务对比。

## 2. 当前阶段判断

AstrBot 已完成 Agent 工程骨架，但尚未证明业务质量稳定优于 CountryCopilot。

| 能力 | 当前判断 |
|---|---|
| Agent 工程骨架 | 约 90%，基本完成 |
| 工具、证据和治理链路 | 约 80%，已具备，可继续复用 |
| SSE、前端和评估工具 | 约 75%，不是当前首要瓶颈 |
| 真实数据覆盖 | 约 45%，是当前主要瓶颈 |
| Composer 泛化能力 | 约 40%，专用分支已大幅收敛，仍需盲测证明 |
| 替换 `/copilot` | 暂不具备条件 |

当前问题不是“模型完全没有运行”，而是模型输出之后叠加了过多车型和评测题专用规则。已知问题容易被修好，未知问题却不能稳定迁移同一套分析方法。

综合完成度按业务可用性而不是测试数量判断，当前约为 **55%-60%**。下一阶段的核心不再是扩大 Agent/Eval 架构，而是让通用 planner 真正拿到 MSRP、配置、月供/RV/TCO、趋势和 BOM 等可引用数据，再用未参与开发的题验证泛化。

## 3. 架构纠偏原则

### 3.1 禁止继续增加评测题特判

- 不为某一条 golden/manual question 增加专用回复分支。
- 不在 Python Composer 中新增 J7、J8、O5、O9、Sorento、EV3、EX30 等车型专属结论模板。
- 允许车型名称参与实体识别、数据查询和检索，但不能决定一段写死的最终回答。
- 修复必须落在可复用层：实体解析、意图路由、工具参数、证据标准化、通用业务框架或数据覆盖。

### 3.2 Composer 只保留通用组合能力

Composer 应按下面的通用输入工作：

```text
Intent + Entities + EvidencePackage + MissingEvidence + AnswerMode
→ Conclusion + Evidence + Implication + Action + ArtifactPlan
```

Composer 可以按 `pricing_analysis`、`competitor_compare`、`market_overview`、`policy_news`、`configuration`、`inventory_bom`、`voc`、`report_generation` 使用通用结构，但不能按评测题或车型名称切换整段答案。

### 3.3 车型知识从代码迁出

车型定位、竞品池、定价方法、产品经理材料和历史判断应进入以下可追溯载体：

- 结构化数据库或数据工具；
- 可检索的产品材料和外部来源；
- 版本化 Playbook / Method Card；
- 用户上传材料及其 EvidenceRef。

代码只负责检索、验证、组合和呈现，不负责保存某车型的最终业务结论。

### 3.4 证据口径必须明确

- 每个关键数字必须带国家、时间范围、筛选条件和来源。
- 当月、YTD、滚动 12 个月和全年数据不能混写成同一口径。
- 同一指标出现冲突时，先标记 scope conflict，不允许 Composer 任取一个数字。
- 没有直接车型价格/配置证据时，不得用市场结构数据伪装成已验证的车型结论。

## 4. 产品输出标准

用户态回答采用 ChatGPT 式正文流，不使用持续变化的回答卡片边框。SSE 文本在原位置持续增长；用户消息、输入、追问、来源、图表和操作区使用轻量圆角容器。

每次有效回答应尽量包含：

- 直接业务结论，而不是工具计划说明；
- 支撑结论的关键证据及口径；
- 从证据推导出的产品经理判断；
- 当前不能确认的部分和原因；
- 下一步可执行动作；
- 适合问题类型的图表、表格或汇报块；
- 能继续推进分析的结构化 follow-up。

开发态 `/astrbot/dev` 保留意图、Evidence Plan、工具调用、EvidencePackage、scope、缺口、成本和评分；用户态默认不展示内部协议和调试结构。

## 5. 当前实施优先级

### P0：守住通用 Composer 边界

1. 保持当前已完成的专用分支收敛，不重新引入车型/评测题最终回答分支。
2. 将新问题修复落在实体解析、意图路由、工具参数、证据标准化和 intent-level 组合器。
3. 保留 Grounding Guard、EvidencePackage 和通用缺口表达。
4. 用行为测试证明通用组合器可承接已知题和盲测题。
5. 默认业务主体必须来自当前请求的 `entities.models / entities.brands`；未指定时只能写“目标产品组合”，不得泄漏默认品牌。

### P0：补真实数据和工具覆盖

优先补齐最影响业务结论的证据：

1. 当前官方 MSRP 和竞品价格走廊；
2. 车型/版本配置差异与工程配置；
3. Leasing 月供、RV、税费和 TCO；
4. BOM、物料号、版本和颜色映射；
5. 可追溯 VOC、政策和外部 Research 来源。

AstrBot 工具层应返回标准化 EvidencePackage；底层数据可以来自 Parquet、PostgreSQL、网页研究或用户材料，Composer 不直接读取底层文件和表。

### P1：通用 Evidence-to-Artifact

- 定价问题：价格走廊、版本价格表、月供/RV 对比。
- 竞品问题：同口径竞品矩阵和可比较指标图。
- 市场问题：规模、份额、动力、级别和趋势图。
- 配置问题：目标车型与竞品配置差异表。
- BOM/库存问题：版本、物料、颜色、数量和生命周期关系表。
- 报告问题：可复制的结论、证据、业务含义和行动块。

Artifact 生成由证据类型和 AnswerMode 决定，不由具体车型名称决定。

### P1：盲测泛化验证

- 建立一组未参与开发、措辞和车型均不同的 blind questions。
- 开发时不得读取盲测期望答案后再写专用分支。
- 同时记录 AstrBot、CountryCopilot、工具、证据、答案和人工评分。
- 已知 30/100 题用于回归，不作为证明泛化能力的唯一依据。

### P2：交付和代码边界收敛

- 拆分 Composer、Eval、Artifact 和超大前端页面，但只做行为保持的渐进式拆分。
- AstrBot worktree 只提交 AstrBot / Agent / MCP 相关文件。
- 共享入口文件只做必要最小改动并单独说明。
- 每个阶段形成可审查 commit 和独立 PR，避免继续积累不可追踪的大批未提交改动。

## 6. 成功标准

AstrBot 只有同时满足以下条件，才进入替换 `/copilot` 的决策阶段：

1. 国家、车型、竞品和时间范围识别稳定，不发生默认国家漂移。
2. 关键问题实际调用对应数据工具，而不是只说明应该调用什么。
3. 关键数字全部可追溯，并明确 month / YTD / rolling-12 / full-year 口径。
4. 没有证据时不编造；有部分证据时仍能给出有边界的业务判断和补证动作。
5. 图表、表格和报告块由真实证据生成，并能直接支持产品经理工作。
6. 在未参与开发的盲测问题中，AstrBot 大多数题的业务评分不低于 CountryCopilot。
7. 已知回归题通过时，不依赖车型名或题目原文命中的专用回答分支。
8. 人工抽查确认答案具有产品经理视角、可执行性和汇报可用性，而不只是规则评分高。

## 7. 立即执行任务

1. 保持 Composer 用户输出核心的源码守卫：车型名不得重新成为结论、建议、标题或报告分支条件，未请求品牌不得出现在通用回答中。
2. 物化可按月查询的市场 time-series，使趋势问题不再只有当月 cross-tab。
3. 导入并验证 lease offer 数据，使月供、RV、合同总成本和 company-car/TCO 问题产生真实 EvidenceRef。
4. 修复工程车型/版本映射，使 configuration compare 能返回可比较 subject 和 feature refs。
5. 扩大当前官方 MSRP 覆盖，并保持国家、时间、来源和车型版本口径。
6. 用当前通用 Composer 跑一组未参与开发的端到端盲测，验证 planner、tool、EvidencePackage、SSE 和 artifact 全链路，而不只是直接调用 composer 单测。
7. 保持现有 ChatGPT 式正文流和 SSE 原位增长，不再扩大用户态调试 UI；盲测稳定后再恢复 AstrBot / CountryCopilot 替换判断。

## 8. 明确非目标

在 AstrBot 的数据覆盖和盲测质量稳定前，不优先推进：

- SaaS 多租户；
- 充值和复杂计费；
- Skill 广场；
- DeepSeek 自动开户；
- 默认入口从 `/copilot` 切换到 `/astrbot`；
- 与 AstrBot 无关的 BOM Admin、MSRP 抓取页面或其他业务线重构。
